Cypescript documentation

Cypescript is a TypeScript-style language that compiles to native machine code through LLVM. Programs read like TypeScript and run at native speed — within ~2% of Rust on compute benchmarks.

hello.csc
let name: string = "world";
println(`Hello, ${name}!`);
Shell
$ cscript -r hello.csc
Hello, world!

Getting started

This guide installs the Cypescript compiler, walks through your first program, and introduces the cscript command-line interface.

Installation

macOS (Homebrew)

Shell
brew tap kr4ckhe4d/cypescript
brew install cypescript
cscript --version

Debian / Ubuntu

Shell
sudo apt-get install -y cmake llvm-dev clang
git clone https://github.com/kr4ckhe4d/Cypescript.git && cd Cypescript
bash packaging/build-deb.sh
sudo apt install ./cypescript_*_*.deb

Arch Linux

Shell
git clone https://github.com/kr4ckhe4d/Cypescript.git
cd Cypescript/packaging/arch
makepkg -si

Note: clang++ must be on your PATH at compile time — cscript uses it to link executables. On macOS it ships with the Xcode Command Line Tools.

Your first program

hello.csc
// Types are TypeScript-style annotations
let greeting: string = "Hello, Cypescript!";
println(greeting);

let year: i32 = 2026;
println(`The year is ${year}`);
Shell
$ cscript -r hello.csc
Hello, Cypescript!
The year is 2026

-r compiles and runs in one step. Without it, cscript hello.csc produces a native executable named hello in the current directory.

The command-line interface

CommandEffect
cscript file.cscCompile to a native executable named after the file
cscript -r file.cscCompile and run immediately
cscript -o name file.cscChoose the executable name
cscript -o out.ll file.cscEmit LLVM IR only (a .ll extension switches modes)
cscript --no-fold file.cscDisable the AST optimizer (constant folding, dead branches)
cscript -v file.cscVerbose output: every compiler stage with timings
cscript --versionPrint the compiler version

How compilation works

cscript runs the full pipeline for you: module resolution (inlining imports) → lexing → parsing → semantic analysis → AST optimization → LLVM IR → clang++ -O2 linked against the precompiled runtime (libcypescript.a). The compiler locates its runtime relative to its own binary, so it works from any directory; set CYPESCRIPT_HOME to override.

TypeScript compatibility

Cypescript's goal is to run TypeScript scripts natively with minute changes. This guide lists what works unchanged, what needs adjusting, and the semantic differences to know about.

Works as-is

  • console.log(...) / console.error(...), including multiple arguments
  • === and !== (treated as == / !=)
  • Math.sqrt, Math.pow, Math.abs, Math.floor, Math.sin, Math.cos, Math.log, Math.exp
  • let/const, type annotations, number (compiles to f64)
  • Interfaces, generics, type aliases, template literals, destructuring
  • Classes with fields, constructors, and methods
  • Arrow functions and closures; .map/.filter/.reduce/.find/.forEach
  • Map / Set, arrays with .push/.pop/.shift/.length, for...of
  • try/catch/finally/throw, switch, break/continue

Typical minute changes

TypeScriptCypescript
x++ as an expression (arr[i++])statement-level x++ only
closures mutating captured primitivescapture an object instead (captures are by-value snapshots)
class A extends Bflat classes only (no inheritance yet)
import from npm packageslocal ./file.csc module imports only
number for hot integer loopsuse i32 for integer math (much faster)

Semantic differences

Closure captures are by-value
A closure snapshots captured variables when it is created. Mutating a captured primitive inside the closure does not affect the outer variable. Capture an object to share mutable state — the pointer is snapshotted, so mutations through it are visible everywhere. See Arrow functions.
Booleans print as 1 / 0
Booleans are native integers; println(true) prints 1.
Integer division
i32 / i32 truncates like C. Use f64 operands for fractional results.

Worked example

The repository ships the same breadth-first-search algorithm as both example/18_bfs_graph.ts and example/18_bfs_graph.csc. The two files differ only in number→i32 annotations and produce byte-identical output.

C++ integration

Cypescript programs link against a C++ runtime library, and you can extend the language with your own C++ functions in minutes.

The standard library

Every executable links libcypescript.a, compiled from src/cypescript_stdlib.cpp. It implements dynamic arrays, Map/Set, string helpers, JSON, file I/O, random numbers, and the exception runtime. These functions are callable directly:

Cypescript
let text: string = "Hello World";
println(string_reverse(text));   // dlroW olleH
println(string_upper(text));     // HELLO WORLD

file_write("data.txt", "saved from Cypescript");
println(file_read("data.txt"));

random_seed(42);
println(random_int(1, 100));

Available functions

Strings
string_reverse, string_upper, string_lower, string_length, string_substring(s, start, len), string_find(s, sub), string_concat(a, b)
Files
file_read(path), file_write(path, content), file_exists(path)
Random
random_seed(n), random_int(min, max), random_double()
Math
math_sqrt, math_pow, math_abs_i32, math_abs_f64, math_floor, math_sin, math_cos, math_log, math_exp — also reachable as Math.*
JSON (string-based)
json_create_object, json_add_string/int/boolean, json_get_string/int/boolean, json_prettify, json_minify, json_is_valid

Adding your own functions

Write a C++ function with C linkage, then compile it in:

my_math_lib.cpp
extern "C" {
    int math_gcd(int a, int b) {
        while (b != 0) { int t = b; b = a % b; a = t; }
        return a;
    }
}
Shell
./compile-with-custom-cpp.sh my_program.csc output src/my_math_lib.cpp
Cypescript
let g: i32 = math_gcd(48, 18);   // 6

Warning: extern "C" is required — without it, C++ name mangling prevents the compiled program from finding your function at link time.

Memory model

Note: runtime allocations (strings, arrays, closure environments) live for the lifetime of the process — Cypescript currently uses script-lifetime memory with no garbage collector. This is by design for short-lived programs; long-running services should be mindful of allocation in hot loops.

Writing a game

Cypescript can open a window, draw, read input and play sound, producing a single native binary. The graphics layer is not built into the compiler — it is an ordinary Cypescript module of declare statements over a small C shim that wraps raylib.

Building

raylib is vendored: CMake fetches and builds it from source and links it statically, so there is no system package to install. 

cmake -S . -B build && cmake --build build --parallel
./build/cscript -r example/game/01_breakout.csc

Use ./build/cscript, not a bare cscript. If Cypescript is already installed, a bare cscript runs that older copy, which has no game runtime and fails with Imported module not found: .../game.csc. The game runtime needs 1.1.0 or newer — check with cscript --version. To put the new build on your PATH: cmake --install build --prefix /opt/homebrew.

Pass -DCYPESCRIPT_VENDOR_RAYLIB=OFF to link a system raylib, or -DCYPESCRIPT_BUILD_GAME_RUNTIME=OFF to leave the game runtime out entirely — the compiler and the language test suite build either way.

The game loop

A complete program
import { } from "game";

openWindow(640, 360, "my game");
setTargetFps(60);

let x: f64 = 100.0;

while (!windowShouldClose()) {
    let dt: f64 = deltaTime();
    if (isKeyDown(KEY_LEFT))  { x -= 200.0 * dt; }
    if (isKeyDown(KEY_RIGHT)) { x += 200.0 * dt; }

    beginFrame();
    clearScreen(rgb(20, 20, 30));
    drawRect(x, 100.0, 80.0, 40.0, rgb(255, 140, 60));
    drawText(`x = ${x}`, 20.0, 20.0, 20, rgb(200, 200, 220));
    endFrame();
}

closeWindow();

import { } from "game" uses a bare module name: game.csc ships with the compiler and is found relative to the cscript binary, so it works from any directory.

Multiply every movement by deltaTime() — the seconds elapsed since the previous frame — so speeds stay the same regardless of frame rate.

Colors are packed i32 values built with rgb(r, g, b) or rgba(r, g, b, a). Key codes are constants (KEY_LEFT, KEY_SPACE, …).

Sound without asset files

makeTone() synthesises a square-wave blip at runtime, so an arcade game can be a single .csc file with no assets beside it.

Synthesised effects
initAudio();
let blip: ptr = makeTone(880.0, 50, 0.30);   // 880 Hz, 50 ms, 30% volume
playSound(blip);

Headless mode

Setting CYPS_HEADLESS=1 runs the whole loop with no window and no drawing, and CYPS_FRAMES caps the run length. The simulation still executes, so a game can be tested in CI. isHeadless() lets a game notice and drive itself. 

CYPS_HEADLESS=1 CYPS_FRAMES=1200 ./build/cscript -r example/game/01_breakout.csc
Breakout ended — score 290, 1200 frames, 51 bricks left

Keeping memory flat

A game loop runs for hours, so anything allocated per frame has to go somewhere. Two things keep memory steady, and a real game needs both.

Frame-scoped strings

A HUD rebuilt every frame from template literals would otherwise leak around 100 bytes per frame. Opt in once, before the loop:

Enabling the frame arena
enableFrameStrings();

// ...later, inside the loop — free instead of leaking
drawText(`SCORE ${score}`, 16.0, 12.0, 20, colText);

Strings built by template literals and + then live only until the next beginFrame(). Everything else — file_read, string_upper, array elements — keeps its permanent allocation.

An arena string does not survive the frame that built it. Anything kept longer — stored in an object field, or pushed to an array you keep — must be copied out with persist(). Strings built before the first beginFrame() are kept automatically, so start-up labels need no special handling.

Pool your entities

Objects are heap-allocated, and nothing frees one when it leaves an array — nothing safely can, since other references may still point at it. Allocate entities once and reuse them, with a flag standing in for spawn and despawn:

The pool idiom
class Bullet {
    x: f64 = 0.0;
    y: f64 = 0.0;
    active: boolean = false;

    spawn(x: f64, y: f64): void {
        this.x = x;
        this.y = y;
        this.active = true;
    }
}

// Allocate once, at start-up
let bullets: Bullet[] = [];
let i: i32 = 0;
while (i < MAX_BULLETS) { bullets.push(new Bullet()); i += 1; }

// Then reuse — despawning is a flag, not a deallocation
function takeBullet(pool: Bullet[]): Bullet {
    let i: i32 = 0;
    while (i < pool.length) {
        let candidate: Bullet = pool[i];
        if (!candidate.active) { return candidate; }
        i += 1;
    }
    return null;
}

removeAt() and clear() remain the right tool when entity churn is not in the hot path. With both techniques applied, the bundled games hold steady memory from 2,000 to 300,000 frames — 83 minutes of play at 60 fps with no growth.

Assets

A relative asset path resolves against the binary, not the working directory — a game gets launched by double-clicking, or from a shell somewhere else entirely. loadTexture() and loadSound() search beside the binary, then assets/, then a macOS bundle's Contents/Resources/, and only then fall back to the working directory so running from a source tree still works.

Loading an asset
let sprite: ptr = loadTexture("player.png");   // found wherever the game runs

// The same resolution, for files you open yourself
println(assetPath("levels/01.txt"));

Shipping

cscript --bundle mygame.csc

Produces a double-clickable mygame.app on macOS (with an Info.plist), or a self-contained directory on other platforms. Assets come from assets/ beside the source — override with --assets DIR — and are placed where the runtime looks for them, so the relative paths in your source keep working after the move.

Current limitations

There is no automatic memory reclamation: heap objects live until the program exits unless you pool and reuse them. Class inheritance (extends) and union types are not implemented. See GAME_ROADMAP.md in the repository for what is planned.

Performance

Cypescript compiles through LLVM -O2 and keeps type information all the way down, which puts it in the same performance class as Rust on compute-bound workloads.

Cross-language benchmark

The exact same algorithm, implemented idiomatically in four languages (benchmarks/cross/), verified to produce identical output, best of 3 wall-clock runs on Apple Silicon (Node v26, Python 3.14, rustc 1.89):

BenchmarkCypescriptNode (TS)PythonRust
Primes < 1M (trial division)0.051s0.146s1.777s0.050s
Fibonacci fib(35), recursive0.025s0.125s0.621s0.026s
Reproduce it
bash benchmarks/cross/run_cross_benchmarks.sh

Why it's fast

Objects are structs
Property layouts are computed at compile time; user.age is a single indexed load — no hash lookups. This change alone measured 2.1× on a 2.5M-property-access benchmark.
Direct calls everywhere
Methods and statically-bound closures compile to direct (inlinable) calls — no vtables, no dynamic dispatch.
Inline callback loops
.map()/.filter()/.reduce() compile to plain loops calling the arrow function directly.
LLVM -O2
The same optimizer Rust and Clang use — inlining, vectorization, constant propagation — runs on every program.

Performance tips

  • Use i32 for integer loops; number is f64 and pays float costs
  • Annotate arrow return types in hot paths to avoid conservative inference
  • Avoid string concatenation inside hot loops (each + allocates)

let & const

The let declaration creates a mutable variable; const creates an immutable binding. Type annotations are optional — the compiler infers types from the initializer.

Syntax

let name = expression;
let name: type = expression;
const name: type = expression;
name
The variable's identifier.
type (optional)
A type annotation such as string, i32, f64, boolean, an array type (i32[]), an interface, or a class name. If omitted, the type is inferred.
expression
The initializer. Required — declarations without initializers are not supported.

Description

Reassigning a const binding is a compile-time error, caught by the semantic analyzer with the offending position. Note that const freezes the binding, not the value: properties of a const object and elements of a const array may still be mutated, matching TypeScript.

Examples

Inference

Cypescript
let count = 42;          // inferred i32
let pi = 3.14159;        // inferred f64
let name = "Ada";        // inferred string
const LIMIT: i32 = 100;

Const violations are compile errors

Cypescript
const MAX: i32 = 10;
MAX = 20;
Compiler output 
Semantic Error: Cannot reassign const variable 'MAX' at line 2, column 1

if...else

The if...else statement executes a block if a condition is truthy, with optional else if chains and a final else block.

Syntax

if (condition) {
  statements
} else if (condition2) {
  statements
} else {
  statements
}
condition
Any expression. Non-zero numbers and non-null pointers (strings, objects, arrays) are truthy; 0, 0.0, false, and null pointers are falsy.

Description

Braces are required around each branch. else if chains may be arbitrarily long; each condition is evaluated only if all previous conditions were falsy.

Examples

Cypescript
let score: i32 = 85;

if (score >= 90) {
    println("Grade: A");
} else if (score >= 80) {
    println("Grade: B");
} else {
    println("Grade: C or below");
}
Output
Grade: B

switch

The switch statement compares an expression against a series of case clauses and executes the first match, with C/JavaScript-style fallthrough.

Syntax

switch (expression) {
  case value1:
    statements
    break;
  case value2:
  case value3:        // stacked cases share a body
    statements
    break;
  default:
    statements
}
expression
An i32, f64, or string expression. String cases are compared by content.
default (optional)
Runs when no case matches. At most one default is allowed.

Description

A case body without a terminating break falls through into the next body, exactly as in JavaScript. Use break to exit the switch.

Examples

Switching on strings

Cypescript
let command: string = "stop";

switch (command) {
    case "start":
        println("starting...");
        break;
    case "stop":
        println("stopping...");
        break;
    default:
        println("unknown command");
}
Output
stopping...

Fallthrough

Cypescript
let day: i32 = 6;
switch (day) {
    case 6:
    case 7:
        println("Weekend!");
        break;
    default:
        println("Weekday");
}
Output
Weekend!

Loops & iteration

Cypescript provides four loop statements: while, do...while, the classic three-part for, and for...of for iterating arrays.

while

while (condition) { statements }
Cypescript
let countdown: i32 = 3;
while (countdown > 0) {
    println(countdown);
    countdown--;
}

do...while

do { statements } while (condition);

The body always runs at least once; the condition is checked afterwards.

for

for (initialization; condition; increment) { statements }

The increment accepts any assignment form: i = i + 1, i++, i += 2, even array or property assignments.

Cypescript
let sum: i32 = 0;
for (let i: i32 = 1; i <= 10; i++) {
    sum += i;
}
println(sum);   // 55

for...of

for (const element of iterable) { statements }
element
A fresh binding for each element; let or const.
iterable
An array (i32[], f64[], or string[]).
Cypescript
let fruits: string[] = ["apple", "banana", "cherry"];
for (const fruit of fruits) {
    println(fruit);
}

See also

  • break & continue

break & continue

break exits the nearest enclosing loop or switch; continue skips to the next iteration of the nearest enclosing loop.

Syntax

break;
continue;

Description

Both statements are validated at compile time: using them outside a valid context is a semantic error with a source position. Inside a switch that is itself inside a loop, continue applies to the loop while break exits the switch.

When a break, continue, or return jumps out of a try block, the exception recovery point is correctly released.

Examples

Cypescript
let total: i32 = 0;
for (let i: i32 = 0; i < 10; i++) {
    if (i == 3) { continue; }   // skip 3
    if (i == 7) { break; }      // stop at 7
    total += i;
}
println(total);
Output
18

function

The function declaration defines a named function with typed parameters and an optional return type. Functions support recursion, generics, and closure-typed parameters.

Syntax

function name(param1: type1, param2: type2): returnType {
  statements
}

function name<T>(param: T): T { ... }          // generic
function name(f: (i32) => i32, x: i32): i32 { ... }  // closure parameter
returnType (optional)
Defaults to void when omitted. Non-void functions return a value with return expression;.
Closure-typed parameters
A parameter annotated with a function type — (i32) => i32 — accepts any arrow function with a matching shape, including inline arrows at the call site.

Description

Functions may be declared in any order; the compiler processes declarations before the main program, so forward references work. Argument counts are validated at compile time with positioned errors. Arguments are coerced to declared parameter types where safe (i32 → f64, boolean widening).

Examples

Recursion

Cypescript
function fib(n: i32): i32 {
    if (n < 2) { return n; }
    return fib(n - 1) + fib(n - 2);
}
println(fib(10));   // 55

Generic functions

Cypescript
function identity<T>(value: T): T {
    return value;
}
println(identity<string>("generics work"));

Higher-order functions

Cypescript
function twice(f: (x: i32) => i32, x: i32): i32 {
    return f(f(x));
}
println(twice(n => n + 1, 40));   // 42

See also

  • Arrow functions
  • class — methods

class

The class declaration defines a blueprint with typed fields, an optional constructor, and methods. new ClassName(args) creates an instance. Instances compile to the same fast native structs as object literals.

Syntax

class Name {
  field1: type;                 // zero-value default
  field2: type = expression;    // explicit default

  constructor(param: type) {
    this.field1 = param;
  }

  method(param: type): returnType {
    statements
  }
}

let instance = new Name(args);
let typed: Name = new Name(args);   // class names are type annotations
Fields
Without an explicit default, fields initialize to their zero value: 0, 0.0, "", or false.
constructor (optional)
Runs after field defaults are applied. Assign fields through this.
Methods
Use this to read and write fields. Calls are direct (no dynamic dispatch) and inlinable.

Examples

Cypescript
class BankAccount {
    owner: string;
    balance: i32;

    constructor(owner: string, opening: i32) {
        this.owner = owner;
        this.balance = opening;
    }

    deposit(amount: i32): i32 {
        this.balance += amount;
        return this.balance;
    }

    withdraw(amount: i32): i32 {
        if (amount > this.balance) {
            throw "insufficient funds for " + this.owner;
        }
        this.balance -= amount;
        return this.balance;
    }
}

let account = new BankAccount("Alice", 100);
println(account.deposit(50));    // 150
println(account.withdraw(30));   // 120
account.balance = 1000;          // direct field assignment works too

Note: class inheritance (extends) is not yet supported — classes are flat. Interfaces support extends for type composition.

interface & type

The interface declaration defines a structural type checked at compile time — with zero runtime cost. type creates a (possibly generic) type alias.

Syntax

interface Name {
  property: type;
  method(): returnType;      // recorded, presence-checked
}

interface Child extends Parent { ... }

type Alias<T> = Map<T, T[]>;

Description

When an object literal is assigned to an interface-typed variable, the compiler verifies structurally that every member exists with a compatible type — a missing or mistyped property is a compile error with a clear message. Extra properties beyond the interface are allowed. extends merges the parent's members transitively.

Interfaces have no runtime representation: no tags, no metadata, nothing in the binary. They are promises checked while compiling.

Examples

Cypescript
interface User {
    name: string;
    age: i32;
}

interface Admin extends User {
    level: i32;
}

let user: User = { name: "Alice", age: 28 };          // ✓ checked
let admin: Admin = { name: "Bob", age: 35, level: 9 }; // ✓ checked

Violations are compile errors

Cypescript
let bad: User = { name: "Dave" };
Compiler output 
Type Error: Object assigned to 'bad' does not satisfy interface 'User':
missing property 'age'

Generic type aliases

Cypescript
type Graph<T> = Map<T, T[]>;

function bfs<T>(graph: Graph<T>, start: T): T[] { /* ... */ }

try...catch & throw

The try...catch statement handles exceptions raised by throw, including throws that unwind through function and method calls. An optional finally block runs on both paths.

Syntax

try {
  statements
} catch (e) {
  statements      // e is bound to the thrown message (string)
} finally {
  statements      // optional
}

throw expression;
e
A const string binding holding the thrown value, scoped to the catch block. Non-string thrown values are converted to strings.
throw expression
Raises an exception. Control transfers to the innermost active catch, unwinding any function calls in between. An uncaught throw prints Uncaught exception: ... and exits with code 1.

Description

Exceptions are implemented with a lightweight setjmp/longjmp runtime — no unwind tables, no overhead when nothing throws. Nested try blocks form a stack; rethrowing from a catch propagates outward. return, break, and continue that exit a try block release its recovery point correctly.

Warning: try nesting is limited to 64 active levels at runtime.

Examples

Cypescript
function risky(n: i32): i32 {
    if (n < 0) {
        throw "negative input: " + n;
    }
    return n * 2;
}

try {
    println(risky(21));    // 42
    println(risky(-1));    // throws — next line never runs
} catch (e) {
    println("caught: " + e);
} finally {
    println("cleanup always runs");
}
Output 
42
caught: negative input: -1
cleanup always runs

  • class — throwing from methods

import & export

The import declaration brings exported members of a local module into scope. Modules are resolved at compile time by inlining each file once.

Syntax

import { name1, name2 } from "./path/to/module";

export function name(...) { ... }
export const NAME: type = value;
"./path/to/module"
A path relative to the importing file. The .csc extension is optional.

Description

Imports are resolved by the compiler driver before parsing: each module's source is inlined exactly once, and import cycles are detected and broken automatically. There is no runtime module loader and no load-order cost. Package imports (npm-style bare specifiers) are not supported.

Examples

math_utils.csc
export function square(x: i32): i32 {
    return x * x;
}
export const GREETING: string = "hello from math_utils";
main.csc
import { square, GREETING } from "./math_utils";

println(GREETING);
println(square(7));   // 49

See also

  • Getting started — the compilation pipeline
  • declare & link — importing from C instead

declare & link

A declare function statement binds a C function so Cypescript can call it directly, and link tells the compiler which libraries to link against. Together they are the foreign function interface: the compiler needs no built-in knowledge of the library you are calling.

Syntax

declare function name(param: type, ...): returnType;
declare function name(param: type, ...): returnType = "c_symbol";

link "libraryName";
link framework "FrameworkName";
link path "/some/lib/dir";
returnType
Omit the : returnType annotation for a void function.
= "c_symbol"
Optional. Calls this C symbol instead of the declared name, so a C-style API can be exposed under natural Cypescript names.
link framework
macOS only — emits -framework Name.
link path
Adds a library search directory. A path that does not exist is ignored.

C ABI types

In addition to the usual types, declarations may use the types that exist specifically to match a C signature.

TypeC equivalentNotes
i32int
i64long long
i8 / u8char
f32float
f64double
stringconst char*NUL-terminated
ptrvoid*Opaque handle; the compiler never inspects it
booleanintZero is false

Description

Declarations are registered before code generation, so a foreign function may be called anywhere in the file, including above its own declaration. Arguments are coerced to the declared parameter types at each call site, and the declared arity is checked at compile time like any other function.

Structs are not passed by value across the boundary. A C API that takes or returns structs needs a thin shim that flattens them into scalars — which is exactly what the game runtime does for raylib.

Nothing is checked against the real library. A signature that does not match the C function is undefined behaviour, not a compile error — the same contract as a C header.

Examples

Calling libc and libm
declare function atan2(y: f64, x: f64): f64;
declare function strlen(s: string): i64;

println(atan2(1.0, 1.0));    // 0.785398
println(strlen("cypescript"));   // 10
Opaque handles
declare function malloc(size: i64): ptr;
declare function free(block: ptr): void;

let block: ptr = malloc(64);
free(block);
Naming a C symbol something friendlier
declare function drawRect(x: f64, y: f64, w: f64, h: f64, color: i32): void = "cyps_rect";

drawRect(10.0, 10.0, 50.0, 50.0, rgb(255, 100, 50));
Linking a library
link path "/opt/homebrew/lib";
link "raylib";
link framework "Cocoa";

Libraries can also be given on the command line, which takes precedence: 

cscript -r game.csc -lraylib -L/opt/homebrew/lib --framework Cocoa

Operators

Cypescript supports the full TypeScript operator set: arithmetic, comparison (including ===/!==), logical with short-circuiting, and compound assignment.

Arithmetic

OperatorMeaningNotes
+addition / concatenationif either operand is a string, both are converted and concatenated
- *subtract, multiplymixed i32/f64 promotes to f64
/divisioni32 / i32 truncates; use f64 for fractions
%remainderworks on i32 and f64
-x !xnegation, logical not

Comparison

==, !=, <, <=, >, >=. The strict forms === and !== are accepted and behave as ==/!= (Cypescript is statically typed, so there is no type coercion to guard against). String equality compares content, not identity.

Logical

&& and || short-circuit and return one of their operands, enabling the TypeScript default idiom:

Cypescript
const neighbors: string[] = graph.get(node) || [];

Bitwise

Integer operands only — applying these to an f64 is a compile error rather than a silent conversion.

OperatorMeaningNotes
& | ^and, or, xor
~xbitwise not
<< >>shift left, arithmetic shift rightwrite without a space between the brackets

Precedence follows TypeScript and C: | binds loosest, then ^, then &, all looser than comparison; shifts bind tighter than comparison but looser than + and -. Integer literals may be written in hex, binary or octal.

Packing a color
let color: i32 = (17 << 16) | (34 << 8) | 51;
println(color);          // 1122867
println(0xFF);           // 255
println(0b1010);         // 10

Assignment

FormEquivalent
x += e, x -= e, x *= e, x /= e, x %= ex = x op e
x++, x--x = x + 1, x = x - 1

All forms work on variables, object properties (obj.count += 1), and array elements (arr[i] *= 2).

Note: x++ is a statement, not an expression — arr[i++] is not supported.

Arrow functions

An arrow function is a function expression that can be stored in variables, passed to functions, and used as a callback. Arrows form closures: they capture variables from the enclosing scope as by-value snapshots.

Syntax

(param1: type, param2: type): returnType => expression
(param1, param2) => expression        // types default to i32, return inferred
param => expression                    // single parameter
(param: type) => { statements }        // block body with explicit return
Untyped parameters
Default to i32. Annotate parameters when working with strings or f64.
Return type
Inferred from the body for common cases; annotate it in ambiguous or hot code.

Description

When an arrow is created, the compiler determines which outer variables the body uses (its captures) and snapshots their current values into a heap environment. Calling the closure later — even from another function — sees those snapshotted values.

Warning: captures are by value, unlike JavaScript. Mutating a captured primitive inside the closure does not affect the outer variable. To share mutable state, capture an object — the pointer is snapshotted, so mutations through it are visible everywhere.

Examples

Basics and captures

Cypescript
let base: i32 = 10;
let addBase = (x: i32): i32 => x + base;
println(addBase(5));    // 15
base = 999;
println(addBase(5));    // still 15 — snapshot capture

Shared state via a captured object

Cypescript
let counter = { count: 0 };
let increment = (): i32 => {
    counter.count += 1;
    return counter.count;
};
println(increment());     // 1
println(increment());     // 2
println(counter.count);   // 2 — mutation is shared

As callbacks and parameters

Cypescript
let numbers: i32[] = [1, 2, 3, 4, 5, 6];
let evens = numbers.filter(x => x % 2 == 0);

function apply(f: (i32) => i32, x: i32): i32 {
    return f(x);
}
println(apply(n => n * 10, 5));   // 50

See also

  • Arrays — .map(), .filter(), .reduce()
  • function — closure-typed parameters

Template literals

Template literals are strings delimited by backticks that may embed expressions with ${expression}.

Syntax

`text ${expression} more text`

Description

Each ${...} is evaluated and converted to a string — integers, floats, and booleans convert automatically. Escape a literal backtick with \` and a literal dollar-brace with \${. Standard escapes (\n, \t) work as in ordinary strings.

Examples

Cypescript
let name: string = "Alice";
let age: i32 = 28;

println(`Hello ${name}!`);
println(`Next year: ${age + 1}`);
println(`${name} is ${age} years old`);
Output 
Hello Alice!
Next year: 29
Alice is 28 years old

Data types

Cypescript is statically typed. Every value has a type known at compile time, which is what lets programs compile to Rust-class native code.

Primitive types

TypeDescriptionExample
i3232-bit signed integer (−2,147,483,648 … 2,147,483,647)let n: i32 = 42;
f6464-bit floating pointlet pi: f64 = 3.14159;
numberTypeScript-compatible alias for f64const r: number = 2.5;
stringimmutable textlet s: string = "hi";
booleantrue / false; prints as 1/0let ok: boolean = true;
voidno value; function returns onlyfunction log(): void
i64, i8, u8, f32sized numerics for matching a C signaturesee the FFI
ptropaque handle to foreign memory; never inspected by the compilerlet tex: ptr = loadTexture("a.png");

Numeric behavior

  • Mixing i32 and f64 in arithmetic promotes to f64: 2 * 3.14 is 6.28
  • i32 / i32 is integer division: 7 / 2 is 3
  • Float literals: 3.14, 0.5, 1.0e-5; integer literals also accept hex (0xFF) and binary (0b1010)

Note: prefer i32 for loop counters and integer math — number/f64 is measurably slower in hot loops.

Composite types

  • Arrays: i32[], f64[], string[]
  • Objects and class instances
  • Interfaces and generic type aliases
  • Function types: (i32, string) => i32 for closure parameters
  • Map<K, V> and Set<T>

Type inference

Cypescript
let count = 7;             // i32
let ratio = 0.5;           // f64
let title = "docs";        // string

Arrays

Arrays are dynamic, growable sequences of a single element type: i32[], f64[], or string[].

Syntax

let name: type[] = [element1, element2, ...];
let empty: string[] = [];
array[index]              // read (0-based)
array[index] = value      // write

Properties & methods

arr.length
Number of elements. Works on any array expression, including chained results like arr.filter(f).length.
arr.push(value)
Appends to the end.
arr.pop()
Removes and returns the last element.
arr.shift()
Removes and returns the first element (queue-style).
arr.map(callback)
Returns a new array of callback(element) results. The result's element type follows the callback's return type — mapping i32 to string yields a string[].
arr.filter(callback)
Returns a new array of elements for which the callback is truthy.
arr.reduce(callback, initialValue)
Folds the array: callback(accumulator, element) per element.
arr.find(callback)
Returns the first matching element (or 0/null if none); stops early.
arr.forEach(callback)
Calls the callback for each element.

Note: callback methods compile to inline loops that call your arrow function directly — there is no dispatch overhead versus a hand-written loop.

Examples

Cypescript
let numbers: i32[] = [1, 2, 3, 4, 5, 6];

let doubled = numbers.map(x => x * 2);              // [2,4,6,8,10,12]
let evens   = numbers.filter(x => x % 2 == 0);      // [2,4,6]
let sum     = numbers.reduce((acc, x) => acc + x, 0); // 21
let firstBig = numbers.find(x => x > 4);            // 5

let labels = numbers.map((x: i32): string => `n${x}`);
println(labels[0]);                                  // n1

// Queue idiom
let queue: string[] = [];
queue.push("first");
queue.push("second");
println(queue.shift());   // first

f64 arrays

Cypescript
let temps: f64[] = [36.6, 37.2, 39.1];
let total = temps.reduce((a: f64, t: f64): f64 => a + t, 0.0);
println(total);   // 112.9

Objects

Object literals create typed records with named properties. Under the hood they are native structs with compile-time layouts — property access is a single instruction, not a hash lookup.

Syntax

let name = {
  property: expression,
  method(param: type): returnType { statements },
  other: function(param: type): returnType { statements },
};

object.property               // read
object.property = value      // write
object.method(args)          // call
let { a, b } = object;       // destructuring

Description

Property types are fixed by the literal; properties cannot be added or removed at runtime (that constraint is where the speed comes from). Objects nest freely — company.employee.name resolves through pointer fields. Passing an object copies its pointer, so functions and closures can mutate shared objects.

Inside a method, this refers to the object and supports both reads and writes, including compound assignment (this.total += x).

println(obj) prints the object's JSON representation, and JSON.stringify/JSON.parse convert to and from JSON strings.

Warning: objects are stack-allocated in the function that creates them — do not return a locally-created object literal from a function. Create it in the caller, or use a class at top level.

Examples

Literals, methods, destructuring

Cypescript
let account = {
    owner: "Alice",
    balance: 100,
    deposit(amount: i32): i32 {
        this.balance += amount;
        return this.balance;
    }
};

println(account.deposit(50));   // 150
account.balance = 42;           // property assignment

let { owner, balance } = account;
println(`${owner}: ${balance}`);  // Alice: 42

Nested objects

Cypescript
let company = {
    name: "TechCorp",
    employee: { name: "Bob", age: 35 }
};
println(company.employee.name);   // Bob
